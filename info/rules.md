## Правила наилучшего единого оформления содержимого тем
временно только Alt Linux

временно только на русском

1. Включать абсолютно все уникальные действия из источников
2. Действия разделять на темы с ### Заголовками
3. #### Заголовками обычно могут быть Установка, Настройка {чего-то}, Проверка {чего-то}, Удаление
4. Действия оформлять как #### название, блок кода, > комментарии

#### В /etc/net/ifaces/ens32/options минимально 
```sample
TYPE=eth
BOOTPROTO=static
CONFIG_IPV4=yes
```
> TYPE(device mode) {eth, vlan, iptun};
BOOTPROTO(protocol) {static, dhcp}

5. Если комментарии громостки, то просто показать примерные частые команды в действии. (пояснение), {вариант, вариант}

#### Настройка NAT
```sample
iptables -t(table) nat -A(chain) POSTROUTING{INPUT} -o(output) eth0 -j(action) MASQUERADE{DROP}
```
6. Использовать комментарии для пояснения возможных вариантов других решений

> аналог BIND9_DLZ(bind) это SAMBA_INTERNAL(команды samba)

7. Несколько команд-действий, если они неотделимы в контексте, могут быть в одном блоке кода
```sample
touch file
rm file
```
8. Использовать в качестве значений частые ens32, 192.168.1.1 или усредненные
9. Вместо картинок указывать какие были проделаны действия, использовать списки, которые могут быть в два уровня
#### Подключение к серверу Кибер Бэкап
- Устройства ->("-" и ">") Добавить -> Самый низ -> МАРКЕР РЕГИСТРАЦИИ (СОЗДАТЬ)
	- СГЕНЕРИРОВАТЬ -> КОПИРОВАТЬ

10. Указать действия списком, если это, например установщик
#### Веб-установщик
- type database: PostgreSQL{MySQL}
- host localhost

> При забывании параметров можно воспользоваться нейронками(llm) или поиском, но всегда необходимо основываться в решении на точные источники
> В качестве редакторов markdown лучше всего использовать консольные вроде nvim, просмоторщиком можно использовать inlyne
